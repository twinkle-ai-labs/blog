# OS 자판을 쓰지 않는다

숫자만 받을 화면에 자판 전체를 띄우면 **화면의 절반을 남에게 내준다.**
그리고 그 절반은 우리 디자인 시스템 밖이다 — 색도 모서리도 움직임도 OS가 정한다.

그래서 키패드를 직접 만들었다. 서랍처럼 아래에서 올라오고, 위쪽에 지금 치고 있는 칸의
이름과 값이 함께 선다. 자판을 안 쓰니 그 자리에 **빠른 키**를 넣을 수 있었다 —
`+1천` `+1만` `+10만` `+100만`. 71,000원을 치는 데 다섯 번 두드릴 이유가 없다.

# 입력칸은 값이 아니라 «식»을 들고 있다

이게 이 앱에서 제일 마음에 드는 결정이다.

「500,000원어치를 69,000원에 사면 몇 주지?」 같은 계산이 실제로 자주 필요하다.
보통은 계산기를 따로 열어 나눈 다음 그 결과를 옮겨 적는다.

그럴 필요가 없게, 칸이 **식을 그대로 보관한다.**

```kotlin
data class CalcState(
    val expressions: Map<Slot, String> = Slot.entries.associateWith { "" },
    …
)
```

`500,000 ÷ 69,000`을 쳤다면 그 사실을 지우지 않는다.
값이 필요할 때만 파서가 읽는다. 재귀 하강 파서를 하나 썼는데,
아는 문법은 `+ − × ÷ ( ) %`와 천 단위 쉼표, 단항 부호, 후위 퍼센트뿐이다.

> 아직 덜 친 식(`2 +`)은 **오류가 아니라 그냥 «아직 없음»**이다.
> 치는 중에 빨간 글씨가 뜨는 것만큼 손을 멈추게 하는 것도 없다.

# 붙여넣기는 걸러서 받는다

증권사 앱에서 값을 복사하면 대개 이렇게 온다.

    72,500원

그대로 넣으면 식이 아니다. 그래서 붙여넣기 전에 식이 될 수 있는 글자만 남긴다.

```kotlin
private val PASTE_ALLOWED_CHAR = Regex("""[0-9,.+\-×÷*/()%−]""")

fun sanitizeForPaste(raw: String): String =
    raw.filter { PASTE_ALLOWED_CHAR.matches(it.toString()) }
```

걸러 낸 뒤에도 식으로 안 읽히면 **붙여넣기 메뉴 자체를 띄우지 않는다.**
눌러도 아무 일이 안 일어나는 메뉴는 「고장난 버튼」으로 읽힌다.

# 주 수와 금액

같은 매수를 「10주」로도 「40만원」으로도 말할 수 있다.
계산식은 하나지만 **사람이 들고 있는 숫자가 다르다** —
증권사 앱을 보고 있으면 주 수를 알고, 통장을 보고 있으면 금액을 안다.

그래서 네 번째 칸의 라벨 자체가 스위치다. 누르면 「매수 수량 ↔ 매수 금액」이 바뀐다.
알약 두 갈래를 따로 세우지 않은 이유는, 그 알약이 종목 이름표·세그먼트와 같은 모양이라
눈이 매번 「이건 뭐지」부터 다시 읽어야 하기 때문이다.

바꿀 때 **그 칸은 비운다.** `10`을 「10주」로 쳐 놓고 금액으로 바꾸면 그 10이 「10원」이 되는데,
그건 사용자가 한 말이 아니다. 뜻이 바뀌는 칸은 비우는 것이 정직하다.

나누는 곳도 하나로 모아 뒀다.

```kotlin
fun buyQuantity(): Double? {
    val fourth = value(Slot.FOURTH) ?: return null
    return when (buyInput) {
        BuyInput.QUANTITY -> fourth
        BuyInput.AMOUNT -> sharesForAmount(fourth, value(Slot.BUY_PRICE) ?: return null)
    }
}
```

화면과 계산이 각자 나누기 시작하면 언젠가 서로 다른 값을 든다.

그리고 나누어떨어지지 않아도 **내림하지 않는다.**
소수점 아래를 버리면 사용자가 넣겠다고 한 돈의 일부가 계산에서 조용히 사라지고,
그러면 평단가가 실제와 어긋난다. 실제로 몇 주를 살 수 있는지는 증권사가 정할 일이다.

# 서랍을 두 번 깨먹었다

키패드는 서랍이라 «바깥을 누르면 닫혀야» 한다. 이걸 세 번 만에 맞췄다.

**첫 번째** — 투명한 층을 본문 **위**에 덮었다.
그랬더니 다른 칸으로 옮기려던 손이 서랍만 닫았다. 칸을 바꾸려면 두 번 눌러야 했다.

**두 번째** — 층을 본문 **아래**에 깔았다.
이번엔 스크롤 영역이 탭을 먼저 가져가서, 결과 카드를 눌러도 아무 일이 없었다.

층 한 장으로는 두 요구를 동시에 만족시킬 수 없다는 걸 그때 알았다.
그래서 «자리»로 정하는 걸 그만두고 **«아무도 안 가져간 탭»**으로 정했다.

```kotlin
.pointerInput(state.keypadOpen) {
    if (!state.keypadOpen) return@pointerInput
    awaitEachGesture {
        awaitFirstDown(requireUnconsumed = false, pass = PointerEventPass.Final)
        val up = waitForUpOrCancellation(PointerEventPass.Final)
        if (up != null && !up.isConsumed) onCloseKeypad()
    }
}
```

`PointerEventPass.Final`은 자식들이 다 본 **뒤에** 온다.
칸·칩·키가 가져간 탭은 여기 닿지 않고, 아무도 원하지 않은 탭만 내려온다.
그것이 곧 «바깥»이다.

> 짝이 되는 장치가 서랍 쪽에 하나 더 있다. 서랍 전체에 걸린,
> 아무 일도 하지 않는 `clickable {}`이다.
> 키 사이 틈을 누른 것은 「아무 키도 아닌 곳」이지 「바깥」이 아니므로 거기서 삼킨다.
> 하는 일이 없어 보여서 **지우기 딱 좋게 생겼는데, 지우면 서랍 안을 눌러도 닫힌다.**

두 번 깨먹은 자리라 지금은 테스트가 셋 지키고 있다 —
안은 안 닫히는가, 밖은 닫히는가, 키는 여전히 눌리는가.
둘은 한 쌍이라 따로 지킬 수 없다. 한쪽만 고치면 다른 쪽이 깨진다.

# 되돌릴 수 있는 일에는 빨강을 쓰지 않는다

키패드에 지우기 키가 셋 있다 — 한 글자 지우기, 칸 비우기(C), 모두 비우기(AC).
셋 다 무채색이다.

한 글자 지우는 일은 겁줄 일이 아니다.
빨강은 되돌릴 수 없는 것에만 남겨 둔다 — 이력 전체 삭제 같은.

대신 **자주 쓰는 키가 손가락에 가깝고, 되돌리기 힘든 키가 멀다.**
색으로 겁주는 대신 거리로 말하는 쪽이다.
