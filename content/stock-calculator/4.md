# 계산은 통화를 모른다

평단가 공식에 단위는 없다.

    (p₁q₁ + p₂q₂) / (q₁ + q₂)

원이든 달러든 루피아든 같은 식이다.
그래서 통화를 «계산에 넘기는 값»으로 두지 않았다. 통화가 정하는 것은 **셋뿐**이다.

```kotlin
enum class Currency(val symbol: String, val prefix: Boolean, val steps: List<Double>) {
    KRW("₩", true, listOf(1_000.0, 10_000.0, 100_000.0, 1_000_000.0)),
    USD("$", true, listOf(1.0, 10.0, 100.0, 1_000.0)),
    EUR("€", false, listOf(1.0, 10.0, 100.0, 1_000.0)),
    …
}
```

기호, 그 기호가 앞에 서는가 뒤에 서는가, 그리고 키패드 빠른 키의 단계.
원은 천 단위로 세지만 달러는 1·10·100·1,000이다 —
`+1천`이 달러 화면에 뜨면 아무도 안 누른다.

저장된 기록은 숫자만 들고 있어서 통화를 바꿔도 그대로다.
**15,000원이 $15,000이 되지, 환산하지 않는다.**
환율을 넣는 순간 이 앱은 네트워크가 필요해지고, 「어제 계산한 것」의 값이 오늘 달라진다.

# 언어와 통화를 묶지 않는다

이게 은근히 흔한 실수다. 「한국어면 원, 영어면 달러」로 두면 코드가 짧아진다.

그런데 **미국의 한국인은 한국어 화면에 달러가 필요하고,
한국의 외국인은 영어 화면에 원이 필요하다.**

그래서 설정에 둘을 따로 뒀다. 첫 통화만 기기 지역에서 고른다.

```kotlin
fun defaultFor(country: String?): Currency = when (country?.uppercase()) {
    "KR" -> KRW
    "JP" -> JPY
    "TW", "HK", "MO" -> TWD
    "AT", "BE", "CY", "DE", … -> EUR
    else -> USD
}
```

그리고 **저장하지 않는다.** 한 번도 고른 적이 없으면 매번 지역을 본다 —
지역을 옮기면 따라간다.

# ¥ 둘을 구별해야 고를 수 있다

엔과 위안은 국제 표기가 둘 다 `¥`다. 목록에 그대로 세웠더니 두 줄이 똑같아 보였다.

    ¥  일본 엔
    ¥  중국 위안

**목록에서 구별되지 않으면 고를 수 없다.** 그래서 위안은 `CN¥`로 적는다.
같은 이유로 통화 이름을 기호와 함께 보여준다 — 「엔 (¥)」, 「위안 (CN¥)」.

그리고 한때 원을 그냥 「원」이라고 적었는데,
독일어 화면의 「원」은 읽을 수 없는 그림이라 국제 기호로 바꿨다.

# 만 단위를 쓰는 말과 K·M을 쓰는 말

세상의 큰 수 세는 법은 두 갈래다.

- **만(10⁴)에서 자리를 바꾸는 말** — 한국어·일본어·중국어
- **천·백만(10³·10⁶)에서 바꾸는 말** — 영어·독일어·스페인어·프랑스어·포르투갈어·이탈리아어·인도네시아어

같은 100만이 한국어로는 `+100만`이고 영어로는 `+1M`이다.

어느 갈래인지는 리소스가 말한다 — `unit_ten_thousand`가 차 있으면 만 쪽,
`unit_million`이 차 있으면 K·M 쪽. 그리고 **한 언어가 둘 다 채우는 일은 없다.**

문제는 그 가정이 리소스 주석에만 적혀 있었다는 것이다.
누가 `unit_million` 한 칸을 채우는 순간 100만 키가 `+1M`이 아니라 `+100만`이 된다.
**앱은 안 죽고 아무도 모른다.**

그래서 판단을 함수로 꺼내고, 열한 로케일의 실제 값을 테스트에 적어 가정 자체를 지키게 했다.

```kotlin
@Test
fun `만 단위와 백만 단위를 함께 쓰는 언어는 없다`() { … }
```

# 비워 둔 복수형 칸은 남이 채운다

lint가 28건을 물어 왔다 — 스페인어·프랑스어·이탈리아어·포르투갈어의 복수형에
`many` 칸이 비어 있다고.

그 네 언어가 `many`를 쓰는 자리는 압축 표기의 백만 단위다
(프랑스어 「1 million **de** jours」).
이 앱이 세는 것은 계산 기록 수라 그 자리에 닿을 일이 없다.

그래도 채웠다. [지난 글]({filename}/stock-calculator/3.md)의 Material `Typography`와 같은 이유다.

> 비워 두면 **안드로이드가 그 수를 만났을 때 스스로 정한다.**
> 「안 쓰는 칸은 비워 둔다」가 아니라 「남더러 채우라」는 뜻이 되는 자리다.

# 서식은 언어의 것이다

통화 목록 한 줄을 이렇게 만들고 있었다.

```kotlin
stringResource(currencyNameRes) + " (" + currency.symbol + ")"
```

**일본어와 중국어는 전각 괄호（）를 쓰고 그 앞에 공백을 두지 않는다.**
코드에서 이어 붙이는 순간 그 화면은 반각 괄호를 쓰는 언어 전용이 된다.

괄호도 서식이므로 리소스로 내렸다.

    <!-- values -->      <string name="currency_option">%1$s (%2$s)</string>
    <!-- values-ja -->   <string name="currency_option">%1$s（%2$s）</string>

날짜도 같다. 「7월 29일」과 「Jul 29」는 서식 자체가 다르므로
`date_month_day` 같은 패턴을 언어마다 번역한다.
코드가 `"${x}원"`을 쓰는 순간 그 화면은 한국어 전용이 된다.

# 인도네시아어는 폴더 이름이 `in`이다

마지막은 함정 하나. 안드로이드의 리소스 한정자는 자바가 쓰던 옛 ISO 코드라
인도네시아어가 **`values-in`**이다. 그런데 `locales_config.xml`은 BCP-47이라
같은 언어를 **`id`**로 적는다.

lint는 이 둘을 다른 언어로 보고 「`values-in`이 선언되지 않았다」고 말한다.
오탐이라 기준선에 넣었는데, 넣으면서 왜 오탐인지를 함께 적어 뒀다 —
폴더를 `values-id`로 «고치면» 그때는 정말로 어느 기기에서도 안 잡힌다.

---

# 마치며

네 편을 쓰고 보니 반복되는 문장이 하나 있다.

**비워 둔 칸은 사라지지 않는다.**
불투명도 토큰이 없으면 리터럴이 번지고, 복수형 칸을 비우면 안드로이드가 정하고,
Material의 타이포 슬롯을 비우면 Roboto가 들어온다.

그리고 또 하나. **앱이 멀쩡히 도는 고장이 제일 나쁘다.**
빌드도 성공하고 화면도 그럴듯한데 조용히 틀린 것들 —
그런 자리는 눈이 아니라 테스트가 지켜야 한다.
