# 템플릿 엔진이라는 것

템플릿 엔진은 **틀**과 **데이터**를 받아 결과 문서를 찍어내는 도구다.
틀에는 "여기에 제목이 들어간다"고만 적어두고, 실제 제목은 데이터가 채운다.

Pelican이 하는 일도 정확히 이것이다. 마크다운 파일에서 제목·날짜·본문을 뽑아
Jinja 템플릿에 넘기면, Jinja가 완성된 HTML을 뱉는다.

![Jinja Logo]({static}/images/pelican/jinja.svg)

Jinja는 Python용 템플릿 엔진으로 **Armin Ronacher**가 만들었고 BSD 라이선스를 따른다.
Django 템플릿과 생김새는 비슷하지만, 샌드박스 안에서 Python에 훨씬 가까운 표현식을 쓸 수 있다.
텍스트 기반이라 HTML뿐 아니라 어떤 형식이든 찍어낼 수 있다.

> **버전 정보**
>
> 이 글은 Pelican `4.12.0` / Jinja `3.1` 기준이다.
> 문법은 Jinja 2 시절부터 거의 그대로라 버전을 크게 타지 않는다.

더 자세한 내용은 [Jinja 공식 문서](https://jinja.palletsprojects.com/)에 있다.

# 중괄호 세 종류만 알면 된다

Jinja 문법은 결국 구분자 세 개로 요약된다. 이것만 구분해도 테마가 읽힌다.

| 구분자 | 이름 | 하는 일 |
|---|---|---|
| `{% ... %}` | 문(Statement) | 조건·반복 등 흐름 제어 |
| `{{ ... }}` | 표현식(Expression) | 값을 화면에 출력 |
| `{# ... #}` | 주석(Comment) | 렌더링되지 않고 사라짐 |

## 문 — 흐름을 만든다

`if`는 데이터가 있을 때와 없을 때를 갈라준다.
글이 하나도 없는 카테고리 페이지가 빈 화면으로 남지 않게 하는 것도 이 일이다.

```jinja
{% if articles %}
    <p>{{ articles|length }} posts</p>
{% elif drafts %}
    <p>only drafts here</p>
{% else %}
    <p>no posts yet</p>
{% endif %}
```

`for`는 글 목록을 만든다. 블로그 테마에서 가장 많이 쓰는 문이다.

```jinja
<ul>
{% for article in articles %}
    <li>{{ article.title }}</li>
{% endfor %}
</ul>
```

반복문 안에서는 Jinja가 `loop`라는 변수를 덤으로 준다.
"첫 글에만 큰 카드를 씌우고 싶다" 같은 요구가 여기서 해결된다.

| 변수 | 값 |
|---|---|
| `loop.index` | 현재 번째 (1부터) |
| `loop.index0` | 현재 번째 (0부터) |
| `loop.first` / `loop.last` | 처음·마지막인지 여부 |
| `loop.length` | 전체 개수 |

```jinja
{% for article in articles %}
    <article class="{% if loop.first %}featured{% endif %}">
        {{ article.title }}
    </article>
{% endfor %}
```

`set`은 값을 미리 담아둔다. 같은 계산을 템플릿 여기저기에 흩어놓지 않게 해준다.

```jinja
{% set total = articles|length %}
<span>{{ total }} notes</span>
```

## 표현식 — 값을 꺼낸다

점(`.`)으로 속성에 접근하고, 파이프(`|`)로 **필터**를 걸어 값을 다듬는다.
필터는 이어 붙일 수 있어서, 왼쪽에서 오른쪽으로 값이 흘러간다고 읽으면 된다.

```jinja
{{ article.title }}
{{ article.title|upper }}
{{ article.summary|striptags|truncate(80) }}
{{ articles|length }}
```

자주 쓰는 필터는 이 정도다.

| 필터 | 하는 일 |
|---|---|
| `length` | 항목 개수 |
| `upper` / `lower` / `capitalize` | 대소문자 변환 |
| `striptags` | HTML 태그 제거 |
| `truncate(n)` | `n`자에서 자르기 |
| `default('값')` | 값이 없을 때 대신 쓸 기본값 |
| `join(', ')` | 리스트를 문자열로 합치기 |

`striptags|truncate`는 목록 페이지의 요약문에 특히 유용하다.
본문에서 그대로 가져온 텍스트에 태그가 섞여 있으면 카드 레이아웃이 통째로 깨지기 때문이다.

## 주석 — 왜 그렇게 했는지 남긴다

`{# #}` 안의 내용은 렌더링 시점에 사라져 결과 HTML에 흔적을 남기지 않는다.
`<!-- -->`와 다른 점이 바로 이것이다. HTML 주석은 방문자가 소스 보기로 다 읽을 수 있다.

```jinja
{# 우측 목차는 본문 제목을 읽어 toc.js가 채운다 #}
```

몇 달 뒤의 나에게 남기는 쪽지는 여기에 적는다.

# 진짜 힘은 상속에 있다

템플릿을 파일마다 따로 만들면, 헤더 하나 고치는 데 파일을 열 개씩 열게 된다.
Jinja는 이 문제를 **상속**으로 푼다. 부모가 뼈대와 **블록**을 선언하면,
자식은 필요한 블록만 덮어쓴다.

`base.html` — 모든 페이지가 공유하는 뼈대다.

```jinja
<html>
<head><title>{% block title %}Twinkle Blog{% endblock %}</title></head>
<body>
    {% block content %}{% endblock %}
</body>
</html>
```

`article.html` — 글 페이지는 제목과 본문만 갈아 끼운다.

```jinja
{% extends "template/base.html" %}

{% block title %}{{ article.title }} - {{ super() }}{% endblock %}

{% block content %}
    <article>{{ article.content }}</article>
{% endblock %}
```

| 키워드 | 하는 일 |
|---|---|
| `{% extends %}` | 부모 템플릿을 상속 |
| `{% block %}` | 자식이 덮어쓸 수 있는 영역을 선언 |
| `{{ super() }}` | 부모 블록의 원래 내용을 그대로 가져옴 |
| `{% include %}` | 다른 템플릿 조각을 그 자리에 끼워 넣음 |

Pelican 테마가 정확히 이 구조로 되어 있다.
`index.html`, `article.html`, `tag.html`이 전부 `base.html`을 상속하고 자기 `content` 블록만 채운다.
헤더나 사이드바처럼 여러 곳에서 반복되는 조각은 `{% include %}`로 따로 떼어두면 된다.

```jinja
{% include "components/_sidebar.html" %}
```

# 마치며

Pelican 테마를 읽고 고치는 데 필요한 Jinja는 사실상 이게 전부다.
흐름을 만드는 **문**, 값을 꺼내는 **표현식**, 구조를 잡는 **상속**.

문법을 알고 나니 테마 폴더가 갑자기 읽히기 시작했다.
