이번에는 만든 블로그를 `GitHub Pages`에 올리고, 커밋할 때마다 자동으로 배포되도록 `GitHub Actions`로 CI/CD를 구축한다.

---

# 1. Repository 생성
Pages로 올릴 Repository를 생성한다.

배포에는 GitHub Actions가 자동으로 발급해주는 내장 `GITHUB_TOKEN`을 사용하므로,
별도의 토큰을 Secrets에 등록할 필요는 없다.

<br>

---

# 2. GitHub Actions로 CI/CD 구축
GitHub Actions Marketplace에 등록된 [GitHub Pages Pelican Build Action](https://github.com/marketplace/actions/github-pages-pelican-build-action)을 이용했다.

## 2.1 requirements.txt 생성
빌드에 필요한 의존성을 명시한다.

```txt
pelican
Markdown
typogrify
```

버전을 고정하고 싶다면 아래처럼 쓴다.

```txt
pelican===4.9.1
```

<br>

## 2.2 Workflow 생성
프로젝트 안에 `.github/workflows` 폴더를 만들고 `pelican.yml` 파일을 생성한다.

```yaml
name: Pelican CI/CD

on:
  push:
    branches:
      - master

jobs:
  build:
    runs-on: ubuntu-latest

    # 내장 GITHUB_TOKEN에 push 권한을 부여한다
    permissions:
      contents: write

    steps:
    - uses: actions/checkout@v4
    - uses: nelsonjchen/gh-pages-pelican-action@0.2.0
      env:
        PELICAN_CONFIG_FILE: publishconf.py
        GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

> ### 💡 GITHUB_TOKEN
> 예전에는 PAT(Personal Access Token)를 발급받아 Secrets에 등록하는 방식을 썼지만,
> 지금은 워크플로우마다 자동으로 발급되는 내장 `GITHUB_TOKEN`에
> `permissions: contents: write`만 주면 된다. 토큰 관리가 필요 없어 더 안전하다.

<br>

## 2.3 추가 설정
배포 환경에 맞춰 설정 파일을 손본다.

`publishconf.py` — 배포될 실제 주소를 적는다.

```python
SITEURL = "https://twinklekhj.xyz/coding/"
```

`pelicanconf.py` — 타임존과 기본 언어를 설정한다.

```python
TIMEZONE = 'Asia/Seoul'
DEFAULT_LANG = 'en'
```

<br>

# 3. 프로젝트 업로드
프로젝트를 Repository에 올린다.

```shell
git init
git add .
git commit -m "first commit"
git branch -M master
git remote add origin [깃 주소]
git push -u origin master
```

푸시하면 Action이 자동으로 실행되고, 빌드 결과가 `gh-pages` 브랜치로 배포된다.

`Settings → Pages`에서 배포 브랜치를 확인하면 블로그가 열린다. 🎉
