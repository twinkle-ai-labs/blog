    목차

      코딩테스트 연습 겸 Python을 붙잡고 있었다. 레퍼런스를 뒤지다 Pelican이라는 걸 발견했고, 그날 밤 블로그 계획이 통째로 바뀌었다.

      Pelican 블로그 만들기 — ① 시작하기 · ② GitHub Pages 배포 · ③ Jinja 문법 · ④ 플러그인

      왜 Jekyll이 아니라 Pelican인가

      GitHub Pages로 블로그를 만든다고 하면 십중팔구 Jekyll 이야기가 나온다. 문제는 Jekyll이 Ruby 위에서 돈다는 것이다. 글 좀 쓰겠다고 안 쓰는 언어의 런타임과 Gemfile까지 집에 들이고 싶지는 않았다.

      Pelican은 같은 일을 Python으로 한다. 마크다운으로 글을 쓰면 HTML 한 덩어리를 뱉는다. 서버도 DB도 없다. 이름은 프랑스어로 "공책"을 뜻하는 calepin의 애너그램이라고 하는데, 공책에 적으면 사이트가 된다는 뜻이니 이름값은 하는 셈이다.

      Jekyll Pelican
      언어 Ruby Python
      글 형식 Markdown Markdown, reStructuredText
      템플릿 Liquid Jinja
      GitHub Pages 기본 지원 Actions로 빌드해서 배포

      정리하면 이렇다. Pelican은 이미 아는 언어로 굴러가고, Jekyll은 GitHub Pages와 더 친하다. 후자는 Actions 워크플로 한 장이면 해결되는 문제였다. 그래서 Pelican을 골랐다.

      더 자세한 소개는 Pelican 공식 사이트에 있다.

      설치

      💡 사전 준비

      Pelican은 Python 기반이다. 터미널에서 python과 pip이 응답하는지 먼저 확인하자.

      프로젝트 폴더 안에 가상 환경부터 만든다. 나중에 Pelican 버전을 올릴 때, 다른 프로젝트까지 같이 흔들리는 일을 막아준다.

      python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate

      이제 Pelican을 설치한다. 대괄호를 빼먹지 말자.

      # 마크다운 지원까지 함께 설치한다
python -m pip install "pelican[markdown]"

# (선택) 따옴표·줄표를 활자처럼 다듬어주는 도구
python -m pip install typogrify

      ⚠️ pelican만 설치하면 생기는 일

      마크다운 확장 없이 설치하면 Pelican이 .md 파일을 읽지 못하고 조용히 건너뛴다. 에러가 아니라 경고 한 줄만 뜨고, 글이 한 편도 없는 멀쩡한 사이트가 만들어진다. 빌드는 성공했는데 목록이 비어 있다면 십중팔구 이 경우다.

      프로젝트 만들기

      pelican-quickstart가 폴더 구조와 설정 파일을 한 번에 깔아준다.

      mkdir pelican-demo
cd pelican-demo
pelican-quickstart

      명령을 실행하면 질문이 줄줄이 나온다. 내가 답한 값은 이렇다.

      Welcome to pelican-quickstart v4.12.0.

> Where do you want to create your new web site? [.]
> What will be the title of this web site? Twinkle Blog
> Who will be the author of this web site? Heejeong Kim
> What will be the default language of this web site? [Korean]
> Do you want to specify a URL prefix? e.g., https://example.com   (Y/n) n
> Do you want to enable article pagination? (Y/n) y
> How many articles per page do you want? [10]
> What is your time zone? [Europe/Rome] Asia/Seoul
> Do you want to generate a tasks.py/Makefile ...? (Y/n) y
> Do you want to upload your website using FTP? (y/N) n
> Do you want to upload your website using SSH? (y/N) n
> Do you want to upload your website using Dropbox? (y/N) n
> Do you want to upload your website using S3? (y/N) n
> Do you want to upload your website using Rackspace Cloud Files? (y/N) n
> Do you want to upload your website using GitHub Pages? (y/N) y
> Is this your personal page (username.github.io)? (y/N) n

      세 개만 짚고 넘어가자.

      • URL prefix — 여기서 n을 눌러도 된다. 실제 배포 주소는 다음 글에서 publishconf.py에 따로 적는다.
      • time zone — 기본값이 Europe/Rome이다. 무심코 엔터를 치면 글 작성 시각이 몇 시간씩 어긋난 채로 굳는다. Asia/Seoul을 직접 넣자.
      • GitHub Pages — y로 답하면 배포용 태스크가 tasks.py에 함께 만들어진다.

      만들어진 구조

      pelican-demo/
├── content/            # 글을 쓰는 곳 (.md)
├── output/             # 빌드 결과 — 여기가 곧 사이트다
├── pelicanconf.py      # 개발용 설정
├── publishconf.py      # 배포용 설정 (개발용을 상속해서 덮어쓴다)
├── tasks.py            # invoke 명령 모음
└── Makefile            # make 명령 모음

      글을 쓰는 방법은 딱 하나다. content/에 .md 파일을 만들고 맨 위에 메타데이터를 적는다.

      Title: 첫 글
Date: 2024-03-27 22:14
Tags: python, pelican
Slug: hello-world
Summary: 한 줄 요약

여기서부터 본문이다.

      Slug가 곧 주소가 되므로 한글보다는 영문으로 적는 편이 낫다.

      빌드하고 띄우기

      빌드는 content/를 읽어 output/을 채우는 일이다.

      # 가장 짧은 형태
pelican

# 경로와 설정을 직접 지정하는 형태
pelican content -o output -s publishconf.py -t themes/twinkle

      글을 쓰는 동안에는 이 한 줄이면 충분하다. 파일을 저장할 때마다 다시 빌드되고, 브라우저에서 http://localhost:8000 으로 확인할 수 있다.

      pelican -lr content -o output -s pelicanconf.py

      자주 쓰는 옵션만 추리면 이 정도다.

      옵션 하는 일
      -o 결과물을 담을 폴더
      -s 사용할 설정 파일
      -t 테마 폴더
      -r 파일이 바뀌면 자동으로 다시 빌드
      -l 로컬 서버 실행 (기본 8000번 포트)
      -d 빌드 전에 출력 폴더를 비운다
      --relative-urls 상대 경로로 링크를 만든다 (로컬 확인용)

      나머지는 필요할 때 pelican --help로 찾아 쓰면 된다.

      💡 -d가 필요한 순간

      Pelican은 기본적으로 output/을 지우지 않고 덮어쓴다. 글을 지우거나 Slug를 바꾸면 예전 HTML이 그대로 남아 유령 페이지가 된다. 주소를 바꿨는데 옛 주소가 계속 열린다면 -d로 한 번 비우자.

      마치며

      여기까지 하면 내 컴퓨터에서만 도는 블로그가 생긴다. 다음 글에서는 이걸 GitHub Pages에 올리고, 푸시 한 번에 배포까지 끝나도록 GitHub Actions를 붙인다.
