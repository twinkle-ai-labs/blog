    목차

      지난 글에서 Jinja 문법을 익히고 테마를 만지기 시작하니 곧 벽에 부딪혔다. 템플릿에 없는 데이터는 아무리 문법을 잘 써도 꺼낼 수 없다.

      글의 대표 이미지를 카드에 띄우고 싶은데 article에는 그런 속성이 없었고, 글 맨 아래에 이전/다음 글을 놓고 싶은데 그 정보도 없었다. 둘 다 플러그인이 채워주는 자리였다.

      Pelican 블로그 만들기 — ① 시작하기 · ② GitHub Pages 배포 · ③ Jinja 문법 · ④ 플러그인

      플러그인은 어디에 있나

      플러그인 저장소가 두 군데라 처음에 좀 헷갈렸다.

      • pelican-plugins organization — 현재. 플러그인마다 독립 저장소로 관리되고 PyPI에 올라와 있다.
      • getpelican/pelican-plugins — 옛날. 한 저장소에 전부 모여 있고, 아직 이쪽에만 남아 있는 것들이 있다.

      어느 쪽에 사느냐에 따라 설치 방법이 갈린다.

      방법 ① pip으로 설치하기

      Pelican 4.5부터 pelican- 네임스페이스 패키지로 배포된 플러그인은 설치만 하면 자동으로 등록된다. 설정 파일에 아무것도 적지 않아도 된다.

      python -m pip install pelican-sitemap
python -m pip install pelican-neighbors

      방법 ② 저장소에 직접 넣기

      pip 패키지가 없는 옛 플러그인은 소스를 받아 프로젝트 안에 둔다.

      git clone --recursive https://github.com/getpelican/pelican-plugins

      필요한 폴더만 골라 옮긴 뒤, pelicanconf.py에 위치와 목록을 알려준다.

      PLUGIN_PATHS = ['path/to/plugins']              # 플러그인들이 모여 있는 상위 폴더
PLUGINS = ['sitemap', 'neighbors']              # 실제로 켤 플러그인

      나는 플러그인들을 테마 폴더 안에 넣고 경로를 이렇게 잡았다. 테마와 플러그인이 한 몸으로 움직여야 다른 곳에 옮겨도 그대로 동작하기 때문이다.

      THEME = "themes/pelican-twinkle"
PLUGIN_PATHS = [THEME + '/plugins']

      ⚠️ 여기서 반나절을 날렸다

      pip으로 설치한 플러그인이 잘 돌고 있었는데, 내장 플러그인을 쓰려고 PLUGINS에 이름을 적은 순간 멀쩡하던 sitemap이 조용히 죽었다.

      PLUGINS를 명시하는 순간 자동 등록이 통째로 꺼지기 때문이다. 목록에 적힌 것만 켜지므로, 섞어 쓸 거라면 pip으로 설치한 것도 함께 적어야 한다. 에러도 경고도 없이 결과물만 사라지는 종류의 문제라, 원인을 찾는 데 한참 걸렸다.

      그래서 최종 목록은 이렇게 됐다. pip으로 설치한 것은 전체 경로로, 직접 내장한 것은 폴더 이름으로 적는다.

      PLUGINS = [
    'pelican.plugins.sitemap',   # pip으로 설치한 것
    'representative_image',      # 테마 안에 내장한 것
    'share_post',
    'neighbors',
    'custom_article_urls',
]

      내가 쓰는 플러그인 다섯 개

      각 플러그인 폴더의 README.md에 설정법이 자세히 적혀 있다. 여기서는 실제로 어떻게 썼는지만 남긴다.

      sitemap — 검색엔진에 지도를 준다

      설치하면 /sitemap.xml이 생긴다.

      SITEMAP = {
    'format': 'xml'
}

      💡 사이트맵이 왜 필요한가

      검색엔진은 크롤러라는 로봇으로 웹을 돌아다니며 정보를 모은다. 이때 어떤 페이지가 어디에 있는지 정리해 건네주는 목록이 사이트맵이다.

      링크를 타고 알아서 찾아가긴 하지만, 이제 막 만든 블로그는 들어오는 링크가 거의 없다. 지도를 직접 쥐여주는 편이 훨씬 빠르다.

      Sitemap 저장소에서 갱신 주기나 우선순위도 설정할 수 있다.

      representative_image — 글의 대표 이미지

      본문의 첫 이미지를 자동으로 뽑아 article.featured_image에 넣어준다. 목록 페이지의 카드 썸네일이 이 값 하나로 해결된다.

      {% for article in articles_page.object_list %}
    {% if article.featured_image %}
        <img src="{{ article.featured_image }}"
             alt="{{ article.title }} 미리보기">
    {% endif %}
{% endfor %}

      {% if %}로 감싸는 걸 잊지 말자. 이미지 없는 글에서 src가 빈 <img>가 남으면 브라우저가 현재 페이지를 다시 요청하는, 꽤 성가신 일이 벌어진다.

      share_post — 공유 링크

      글마다 공유 URL을 만들어준다. 버튼 생김새는 내가 정하고, 주소만 받아 쓰는 방식이라 마음에 들었다.

      {% if article.share_post %}
<ul>
    <li>
        <a href="{{ article.share_post['email'] }}" target="_blank">Email</a>
    </li>
    <li>
        <a href="{{ article.share_post['twitter'] }}" target="_blank">Twitter</a>
    </li>
    <li>
        <a href="{{ article.share_post['facebook'] }}" target="_blank">Facebook</a>
    </li>
    <li>
        <a href="{{ article.share_post['linkedin'] }}" target="_blank">LinkedIn</a>
    </li>
</ul>
{% endif %}

      지원 목록은 facebook, email, twitter, diaspora, linkedin, hacker-news, reddit. 해외 기준이라 국내에서 많이 쓰는 카카오톡이 없다. 이건 나중에 직접 붙여야 할 숙제로 남겨뒀다. 😢

      custom_article_urls — 주소 정리하기

      기본값으로 두면 모든 글이 루트에 평평하게 쌓인다. 카테고리를 주소에 넣고 싶었다.

      • 전: https://blog.twinklelabs.kr/create-pelican-site.html
      • 후: https://blog.twinklelabs.kr/pelican/create-pelican-site.html
      ARTICLE_URL = "posts/{slug}.html"           # 기본 규칙

CUSTOM_ARTICLE_URLS = {                     # 카테고리별 예외
    'pelican': {
        'URL': '{category}/{slug}.html',
        'SAVE_AS': '{category}/{slug}.html'
    }
}

      URL은 링크에 쓸 주소, SAVE_AS는 실제로 파일이 저장될 경로다. 둘은 반드시 같이 바꿔야 한다. 하나만 고치면 링크는 있는데 파일이 없는, 혹은 그 반대의 404가 생긴다.

      ⚠️ 주소를 바꾸면 남는 흔적

      이미 배포된 글의 주소를 바꾸면 예전 HTML이 output/에 그대로 남는다. DELETE_OUTPUT_DIRECTORY = True를 켜두거나 pelican -d로 한 번 비워주자.

      neighbors — 이전 글 / 다음 글

      읽던 사람이 다음에 갈 곳을 만들어준다. 시리즈 글이라면 특히 아쉬운 자리다.

      {% if article.prev_article_in_category %}
    <a href="{{ SITEURL }}/{{ article.prev_article_in_category.url }}">
        {{ article.prev_article_in_category.title }}
    </a>
{% endif %}

      전체 글 기준의 prev_article / next_article도 있지만, 나는 같은 카테고리 안에서만 이어지도록 _in_category 쪽을 썼다. 이 글 아래에 붙어 있는 링크가 그 결과다.

      마치며

      Pelican은 널리 쓰이는 도구가 아니라 한국어 레퍼런스가 거의 없다. 막히면 결국 플러그인 저장소의 README.md와 소스를 직접 읽게 되는데, 그게 이번 시리즈에서 가장 오래 걸렸지만 가장 남은 시간이기도 했다.

      네 편에 걸쳐 설치부터 배포, 테마, 플러그인까지 왔다. 이제 이 블로그는 마크다운 파일 하나를 커밋하는 것만으로 갱신된다. 필요한 기능이 생기면 그때 하나씩 더 붙이면 된다. 🤗
