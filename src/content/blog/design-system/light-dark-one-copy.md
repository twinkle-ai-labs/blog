디자인 시스템 목업에서 브랜드색을 확인하다가 주석과 실제 값이 다른 것을 발견했습니다.

```css
/* Aurora 는 #7040D9 */
--brand: #6F3DE0;
```

설명에는 `#7040D9`라고 적혀 있었지만 화면을 그리는 값은 `#6F3DE0`이었습니다. 디자인 시스템을 설명하는 목업 자체가 기준과 다른 색을 사용하고 있었습니다.

이 시리즈에서는 같은 값을 유지하는 방법을 색, 치수, 시스템 전체의 순서로 다룹니다. 첫 편은 테마별로 흩어진 색 정의를 합친 기록입니다.

## 테마마다 색 표가 따로 있었습니다

당시 색 표를 여섯 벌로 정리했으며, 적용 위치는 다음과 같았습니다.

| 위치 | 적용되는 경우 |
|---|---|
| `:root` (라이트) | 기본 |
| `@media (prefers-color-scheme: dark)` | 시스템이 다크일 때 |
| `[data-theme="dark"]` | 사용자가 다크를 고를 때 |
| `[data-theme="light"]` | 사용자가 라이트를 고를 때 |
| `.phone` 스킨 × 3 | 목업 안의 폰 목업 |

뒤쪽 블록 하나에 옛 보라 `#6F3DE0`이 남아 있었습니다. 이 선언이 앞의 값을 덮어쓰면서 화면에도 옛 색이 나타났습니다.

문제는 수정할 위치를 전부 확인하기 어렵다는 점이었습니다. 코드를 검색해 바꾸더라도, 화면에서는 현재 선택된 테마만 확인하게 됐습니다. 특히 `[data-theme="light"]`는 사용자가 라이트를 직접 골랐을 때만 적용됩니다. 시스템 기본 라이트에서는 `:root` 값이 쓰이므로 수동 선택 경로의 오류를 놓치기 쉬웠습니다.

## 색 정의를 한곳에 모았습니다

`light-dark()`로 라이트와 다크의 값을 같은 선언에 적었습니다.

```css
:root {
  color-scheme: light dark;

  --token-bg:      light-dark(#F8F6FC, #110D19);
  --token-text:    light-dark(#21182D, #FAF7FF);
  --token-primary: light-dark(#7040D9, #986CF4);
}
```

어느 색을 사용할지는 해당 요소의 `color-scheme`이 정합니다. 사용자가 테마를 직접 선택하는 경우에는 색 표를 다시 쓰지 않고 `color-scheme`만 바꿨습니다.

```css
:root[data-theme="dark"]  { color-scheme: dark; }
:root[data-theme="light"] { color-scheme: light; }
```

색을 수정할 때 찾아갈 곳이 하나로 줄었습니다. 테마를 고르는 코드와 색을 정의하는 코드도 분리됐습니다.

### 짧은 이름은 원래 토큰을 참조하게 했습니다

화면에서 더 짧은 변수명이 필요할 때도 값을 복사하지 않았습니다.

```css
/* ✗ 두 벌이 됩니다 */
--bg: #F8F6FC;

/* ○ 가리킵니다 */
--bg: var(--token-bg);
```

`--bg`가 `--token-bg`를 참조하면 원래 토큰을 바꿀 때 함께 반영됩니다. 색을 직접 적으면 두 값을 따로 관리해야 합니다.

## color-scheme은 루트에 선언했습니다

`color-scheme`은 `light-dark()`의 선택뿐 아니라 브라우저가 그리는 스크롤바와 `<input>`, `<select>`, 체크박스에도 영향을 줍니다. 페이지 배경을 그리기 전의 캔버스에도 적용됩니다.

어두운 페이지에서 이 설정을 빠뜨리면 브라우저가 밝은 테마의 컨트롤을 사용할 수 있습니다. `body`에만 선언했을 때는 뷰포트 스크롤바가 따라오지 않으므로, 테마를 지정하는 루트 요소에 뒀습니다.

작업 당시 확인한 `light-dark()`의 지원 시작 버전은 다음과 같습니다.

| 브라우저 | 지원 시작 |
|---|---|
| Chrome | 123 |
| Safari | 17.5 |
| Firefox | 120 |

색은 `light-dark()`로 한곳에 정의하고, 수동 선택은 루트의 `color-scheme`으로 처리하도록 정리했습니다. 짧은 이름이 필요한 곳에서는 기존 토큰을 참조합니다.
