결과 카드의 `IconBadge`와 이력의 `KindBadge(iconOnly)`가 같은 크기여야 했다.
코드는 이렇게 생겼다.

```kotlin
// ResultCard.kt
Box(modifier = Modifier.size(24.dp))   // KindBadge 와 같은 크기

// HistoryRow.kt
Box(modifier = Modifier.size(24.dp))   // IconBadge 와 같은 크기
```

값은 맞았다. 묶여 있지는 않았다.

---

# 주석은 읽는 사람에게만 말한다

한쪽을 26으로 고치면 다른 쪽은 24로 남는다. 컴파일러는 아무 말도 안 한다.
**그리고 한쪽을 고치는 사람은 대개 다른 쪽을 읽지 않는다.**

주석의 문제는 틀릴 수 있다는 게 아니다. 주석은 **강제하는 힘이 없다.**
「같아야 한다」는 사실이 사람의 기억에만 얹혀 있다.

이름은 다르다. 컴파일러가 따라간다. 한 번 고치면 둘이 같이 움직인다.

```kotlin
// Badges.kt
internal val KindBadgeIconOnlySize = 24.dp
```

이제 두 자리가 이 이름을 가리킨다.

---

# 같은 꼴을 찾다가 이미 어긋난 것을 봤다

`// 저쪽과 같은`이라는 주석을 전부 찾아봤다. 그러다 이걸 봤다.

```kotlin
// StockManageScreen.kt
IconButton(modifier = Modifier.size(32.dp))   // IconBadgeSize 와 맞춤
```

`IconBadgeSize`는 **28**이다.

위쪽의 주석 둘은 「같은 크기(28dp)」라고 말하고 있었다.
**주석이 «같다»고 말하는 채로 값은 이미 갈라져 있었다.**

언제 갈라졌는지는 모른다. 아무도 모른다. 그게 요점이다.

---

# 어긋난 것은 따로 간다

여기서 한 가지를 참아야 했다.

값이 **같은 동안**에는 이름 하나로 묶어도 화면이 안 바뀐다.
안전한 리팩토링이다.

값이 **이미 다르면** 이름을 가리키게 하는 순간 화면이 바뀐다.
32였던 버튼이 28이 되거나, 28이었던 배지가 32가 된다.

그러니 이건 리팩토링이 아니라 **디자인 변경**이다.
띄워 보고 어느 쪽이 맞는지 정한 뒤에 간다. 커밋도 따로 간다.

---

# 그런데 사다리 토큰을 가리키지는 않았다

여기서 유혹이 하나 더 있었다. 「토큰이 있는데 왜 새 상수를 만드나?」

우리 아이콘 사다리는 이렇다.

```
12 · 16 · 20 · 26
```

**24가 없다.** 그리고 간격 사다리에는 `Spacing.s3`가 24로 있다.

그래서 `Spacing.s3`를 가리키고 싶어진다. 값이 맞으니까.

안 했다. **배지 한 변이 간격 한 칸과 같은 숫자인 것은 우연이다.**

간격이 바뀐다고 배지가 따라 바뀔 이유가 없다.
우연을 묶으면 나중에 간격 사다리를 손볼 때 배지가 같이 움직인다.
그리고 그때 왜 움직였는지 아무도 모른다.

> 컴포넌트의 광학 치수는 **그 파일의 이름 붙은 상수**로 둔다.

토큰은 「같은 이유로 같아야 하는 것」을 묶는 도구다.
「지금 숫자가 같은 것」을 묶는 도구가 아니다.

---

# 이름은 읽히는 대로 짓는다

처음에 `KindBadgeIconSize`라고 지었다가 바꿨다.

- `KindBadgeIconSize` → 「배지 **안 아이콘**의 크기」로 읽힌다
- `KindBadgeIconOnlySize` → 「아이콘만 남긴 **모드**의 상자 한 변」

우리가 묶으려던 건 후자다. 앞의 이름을 그대로 뒀으면
다음 사람이 아이콘 크기를 고치려다 상자를 고쳤을 것이다.

---

# 정리

- `// 저쪽과 같은`이라는 주석을 보면 **이름 하나로 바꾼다.**
- 값이 같은 동안은 안전한 리팩토링이고, **이미 어긋났으면 디자인 변경**이다. 따로 간다.
- 숫자가 같다고 묶지 않는다. **같은 이유로 같아야 하는 것**만 묶는다.
- 이름은 읽히는 대로 짓는다.

같아야 하는 것은 주석에 적을 게 아니라 **한 곳에 두고 가리킬** 것이다.
[라이트·다크를 네 벌 적으면 그중 하나가 몰래 달라진다](/design-system/light-dark-one-copy.html)와 같은 법이다 —
거기서는 색이었고 여기서는 치수일 뿐이다.
