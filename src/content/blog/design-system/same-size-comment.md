결과 카드의 `IconBadge`와 이력의 `KindBadge(iconOnly)`는 같은 크기를 사용해야 했습니다. 두 구현에는 값과 주석이 각각 들어 있었습니다.

```kotlin
// ResultCard.kt
Box(modifier = Modifier.size(24.dp))   // KindBadge 와 같은 크기

// HistoryRow.kt
Box(modifier = Modifier.size(24.dp))   // IconBadge 와 같은 크기
```

이 상태에서는 한쪽을 바꿔도 다른 쪽에 반영되지 않습니다. ‘같은 크기’라는 관계는 주석을 읽고 기억하는 사람에게만 맡겨져 있었습니다.

## 두 구현이 같은 상수를 참조하게 했습니다

한쪽을 26으로 바꾸면 다른 쪽은 24로 남아도 컴파일 오류가 나지 않습니다. 이 관계를 코드에 남기기 위해 공통 상수를 만들었습니다.

```kotlin
// Badges.kt
internal val KindBadgeIconOnlySize = 24.dp
```

두 배지 모두 `KindBadgeIconOnlySize`를 참조하게 하면 값을 한 번 수정해 함께 바꿀 수 있습니다. 기존 두 값이 모두 24.dp였으므로 이 변경 자체로 화면 크기는 달라지지 않았습니다.

## 이미 값이 다른 곳도 있었습니다

`// 저쪽과 같은`이라는 주석을 찾아보던 중 종목 관리 화면에서 다른 사례를 발견했습니다.

```kotlin
// StockManageScreen.kt
IconButton(modifier = Modifier.size(32.dp))   // IconBadgeSize 와 맞춤
```

이 버튼은 32.dp였지만 `IconBadgeSize`는 28이었습니다. 위쪽의 주석 둘에는 ‘같은 크기(28dp)’라고 적혀 있었습니다. 주석은 같다고 설명하는데 실제 값은 달랐고, 언제부터 달랐는지는 확인하지 못했습니다.

여기서는 공통 이름으로 바꾸기 전에 크기를 결정해야 했습니다. 32를 28로 바꾸든, 28을 32로 바꾸든 화면이 달라지기 때문입니다. 같은 값의 중복을 제거하는 작업과 구분하고, 화면을 확인한 뒤 디자인 변경으로 별도 커밋에 다루기로 했습니다.

## 간격 토큰을 재사용하지 않은 이유

당시 아이콘 크기 단계에는 24가 없었습니다.

```
12 · 16 · 20 · 26
```

간격 토큰에는 24인 `Spacing.s3`가 있었지만, 배지 크기를 그 토큰에 연결하지 않았습니다. 간격을 조정할 때 배지의 한 변도 바뀌어야 할 이유는 없었습니다.

그래서 이 치수는 컴포넌트 파일의 이름 붙은 상수로 뒀습니다. 같은 숫자라는 이유만으로 묶지 않고, 함께 변경돼야 하는 두 배지만 같은 상수를 참조하게 했습니다.

## 상자 크기를 설명하는 이름으로 바꿨습니다

처음 이름은 `KindBadgeIconSize`였습니다. 배지 안의 아이콘 크기로 읽힐 수 있어 `KindBadgeIconOnlySize`로 바꿨습니다.

실제로 지정하는 것은 아이콘 자체가 아니라 ‘아이콘만 표시하는 모드’의 상자 한 변입니다. 이름에서도 그 대상을 구분하도록 했습니다.

이 작업에서는 같은 값인 배지를 공통 상수로 묶었고, 이미 다른 값인 버튼은 별도로 판단할 디자인 변경으로 남겼습니다.
