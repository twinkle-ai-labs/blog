## 들어가며

Pocket PDF에 구독 기능을 붙이면서 보상형 광고를 추가했습니다. 광고를 보면 폴더 슬롯을 더 받을 수 있게 하는 기능이었습니다. 배너와 전면 광고는 이미 실제 ID로 바꿨는데, 새 보상형 광고에는 Google 테스트 ID가 남아 있었습니다.

```
ca-app-pub-3940256099942544/...   ← Google 테스트 ID
```

`admob-ids.sh`가 이 값을 잡아 출시를 막았습니다. 개발 중에 광고가 뜨고 보상이 지급되는 것은 확인했지만, 실제 광고 단위는 아직 준비하지 않은 상태였습니다.

## 테스트 ID를 지우자 다른 빈틈이 보였습니다

스크립트는 두 가지를 확인했습니다. Google 테스트 ID가 들어 있는지, 필요한 값이 비어 있는지였습니다. 테스트 ID 검사에는 보상형도 걸렸지만, 빈 값 검사의 대상은 다음 두 개뿐이었습니다.

```bash
CHECK_TARGETS="ADMOB_BANNER ADMOB_INTERSTITIAL"
```

보상형 ID를 빈 문자열로 바꾸면 테스트 ID 검사에도, 빈 값 검사에도 걸리지 않았습니다. 앱에 보상형을 추가하면서 이 목록을 그대로 둔 탓이었습니다.

## 출시 검사와 광고 준비 상태를 나눴습니다

빈 값 검사에 `ADMOB_REWARDED`를 추가했습니다. 이제 실제 ID가 없다는 이유로 출시 검사가 멈췄습니다.

AdMob 콘솔에서 보상형 광고 단위를 아직 발급받지 못했으므로 ID는 빈 값으로 뒀습니다. 실제 ID를 받아 채우기 전까지 검사는 실패하는 상태로 남겼습니다.

앱 안의 준비 상태도 함께 나눴습니다. `AdUnits.isRewardedReady`를 기존 `isReady`와 별도로 두었습니다. 보상형 ID가 없다는 이유로 이미 실제 ID를 가진 배너까지 사용할 수 없게 만들 필요는 없었습니다.

## 마치며

빈 값 검사에는 보상형 광고를 포함했고, 앱 안에서는 광고별 준비 상태를 따로 확인하게 했습니다. 실제 ID가 없는 보상형 광고 때문에 배너까지 막히지는 않지만, 출시 검사는 멈추는 상태입니다.

보상형 광고 단위를 발급받는 일은 그날 마치지 못했습니다.
