커밋 작성자가 옛 메일로 남아 있었다. 물타기 계산기 122개, 루트 32개 — 합쳐 154개.
`filter-branch`로 이력을 다시 썼다.

며칠 뒤에 보니 스토어 사진 검사(`fresh.sh`)가 떨어져 있었다.

```
fatal: bad object 8c7235f…
```

---

# 무엇이 깨졌나

이 검사는 «스토어 스크린샷이 최신 화면과 같은가»를 본다.
방법은 이렇다.

`docs/store/shots/reviewed-at`이라는 파일에 **사람이 눈으로 봐 둔 시점의 커밋 해시**를 적어 둔다.
검사는 그 해시를 읽어서 `git log -1 <해시>`로 그때 이후에 화면 코드가 바뀌었는지 본다.

이력을 다시 쓰면서 그 해시가 **새 이력에 없는 이름**이 됐다.

---

# 알고 있었는데도 깨졌다

이 부분이 제일 뼈아프다.

백로그 114번에 이렇게 적혀 있었다.

> 이력을 다시 쓰면 `reviewed-at`도 어긋난다

미리 적어 뒀다. 그날 새벽에 잘못 섞인 커밋을 되감지 않은 이유이기도 했다 —
«되감으면 저게 깨진다»를 알고 있었으니까.

그런데 정작 계획된 재작성에서는 그 자리를 잊었다.
**알고 있는 것과 그 순간 손이 그 자리로 가는 것은 다르다.**
그리고 도구는 그 자리를 몰랐다.

---

# 왜 조용했나

해시는 이력 안에서만 뜻이 있다. 이력이 다시 쓰이면 옛 해시는
**어느 저장소에도 없는 이름**이 된다.

그때 그것을 읽는 검사는 «틀렸다»로 떨어지지 않는다. **«없다»로 떨어진다.**

```
fatal: bad object …
```

`bad object`는 «비교해 보니 다르다»가 아니라 «비교할 대상이 없다»다.
그리고 없는 것은 소리를 내지 않는다 — 검사는 실패했는데,
그 실패가 «스크린샷이 낡았다»는 신호로 읽히지 않는다.

---

# 두 번째 재작성에서 같이 옮겼다

`filter-branch`의 `map`을 써서 두 가지를 함께 새 해시로 옮겼다.

1. `reviewed-at` 파일 안의 해시
2. **그 해시를 본문에 적은 커밋 메시지 둘** — 「사진을 봐 두었다고 적는다 (…)」

두 번째를 빠뜨릴 뻔했다. 커밋 메시지 안에도 해시가 있었다.

---

# 검사가 읽는 해시와 사람이 읽는 해시를 가른다

금고(`vault/`)의 일지에도 옛 해시가 잔뜩 적혀 있다. 그건 안 고쳤다.

| | 검사가 읽는 해시 | 사람이 읽는 해시 |
|---|---|---|
| 어디 | `reviewed-at` 같은 파일 | 일지·기록 |
| 이력을 고치면 | **같이 고친다** | **그대로 둔다** |
| 왜 | 읽는 도구가 있고, 없으면 깨진다 | 「그때 그렇게 적혔다」는 사실이다 |

일지의 옛 해시를 고치면 오히려 거짓이 된다.
되돌린 결정을 지우지 않는 것과 같은 이유다 — 기록은 그때의 사실이지 현재 상태가 아니다.

---

# 다음에 어떻게 하나

## 이력을 다시 쓰기 전에 해시를 담은 파일을 먼저 찾는다

```bash
git grep -E '[0-9a-f]{7,40}'
```

찾은 자리를 `filter-branch`의 `map`이나 `git replace`로 같이 옮긴다.

## 검사가 해시를 읽으면 «없는 해시»를 오류로 낸다

`bad object`가 통과나 조용한 실패가 되지 않게 한다.

```bash
git cat-file -e "$REVIEWED_AT^{commit}" 2>/dev/null || {
  echo "reviewed-at 의 해시가 이 이력에 없다 — 이력이 다시 쓰였나?" >&2
  exit 1
}
```

«없다»와 «낡았다»는 사람에게 다른 말이어야 한다.

## 어디 있는지를 백로그가 아니라 순서에 적는다

백로그에 적어 둔 것은 **읽을 이유가 있을 때만** 읽힌다.
이력을 고치는 사람은 그날 백로그를 안 본다.

그러니 「이력 재작성 절차」라는 문서에 적는다.
그 문서는 그 일을 하는 사람이 반드시 여는 문서니까.

---

# 남는 생각

해시를 파일에 적는 건 흔한 일이다. 락 파일, 캐시 키, 「여기까지 확인함」 표시.
전부 편하고 전부 같은 성질을 갖는다.

**그 파일은 코드가 아니라 이력의 일부다.** 이력을 고치는 손이 그 파일도 같이 고쳐야 한다.
