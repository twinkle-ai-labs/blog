구글 플레이 등록정보를 Gradle Play Publisher(GPP)로 올리고 있다.
명령 한 줄이면 텍스트도 이미지도 다 올라간다.

```bash
./gradlew publishReleaseListing
```

돌렸다. 며칠이 지났는데 **스토어 이미지가 안 바뀌어 있었다.**

---

# 텍스트와 이미지가 한 편집(edit)에 들어간다

플레이 API는 «편집(edit)»이라는 단위로 움직인다.
편집을 열고, 그 안에서 이것저것 바꾸고, 마지막에 커밋한다.
커밋 전까지는 아무것도 반영되지 않고, 커밋하면 전부 반영된다.

**원자적이다.** 반쯤 올라간 스토어가 생기지 않는다.

GPP 4.1.1은 등록정보 텍스트와 이미지를 **같은 편집**에서 올린다.
그러니 이 둘은 함께 성공하거나 함께 실패한다.

---

# 없는 로케일 하나가 전부를 죽였다

새 언어를 추가하면서 `graphics/` 폴더를 여러 로케일에 만들어 뒀다.
그중 일부는 **스토어에 아직 존재하지 않는 로케일**이었다.

GPP는 이미지를 올리기 전에 현재 이미지 목록을 GET으로 가져온다.
스토어에 없는 로케일에서는 이게 404로 죽는다.

```
Listing for language 'fr-FR' not found
```

그리고 그 편집은 원자적이므로, **이미 잘 있던 ko-KR의 이미지까지 통째로 버려졌다.**

빌드 로그 끝은 이랬다.

```
FAILED
```

---

# 원자성의 뒷면

원자성은 좋은 성질이다. 반쯤 올라간 스토어를 막아 준다.

대신 **실패의 원인이 전체의 아무 데나 있을 수 있게 한다.**
그리고 로그는 마지막 예외만 보여 준다.
«무엇이 안 올라갔는가»는 로그에 없다. 스토어 쪽을 열어 봐야 안다.

여기서 두 번째 함정이 나온다. **콘솔은 «검토 중인 것»과 «올라간 것»을 구분해 주지 않는다.**
눈으로 보면 바뀐 것 같아 보인다. 그래서 콘솔이 아니라 API를 봐야 한다.

---

# 확인하는 법 — sha1을 맞춰 본다

편집을 하나 만들고, 이미지 목록을 읽고, 해시를 로컬 파일과 맞춰 보고, 편집을 지운다.
읽기만 하니까 지워도 아무 일도 안 일어난다.

```bash
# 1. edit 을 만든다
# 2. GET listings/{lang}/phoneScreenshots → 각 이미지의 sha1
# 3. 로컬 파일의 shasum 과 맞춘다
shasum fastlane/metadata/android/ko-KR/images/phoneScreenshots/*.png
# 4. edit 을 DELETE
```

해시가 맞으면 올라간 것이고, 다르면 안 올라간 것이다.
**눈으로 본 콘솔은 증거가 아니다.**

---

# 우회로 — 두 번 돌린다

스토어에 없는 로케일이 있으면 이렇게 한다.

1. 새 로케일의 `graphics/`를 잠깐 치워 두고 한 번 돌린다 → **로케일이 생긴다**
2. 되돌리고 다시 돌린다 → **이미지가 올라간다**

저장소 트리는 결국 그대로다. 명령을 두 번 돌릴 뿐이다.

## 막힌 길 하나

«REST로 직접 쳐서 로케일만 먼저 만들면 되지 않나» 싶어서 해 봤는데 안 됐다.
`edits:validate`는 200을 주는데 `edits:commit`이 HTML 404를 준다.

커밋은 플러그인에게 맡기는 수밖에 없었다. 되돌린 시도지만 적어 둔다 —
안 적으면 다음에 또 같은 자리를 판다.

---

# 같은 꼴을 전날에도 봤다

바로 전날 «소스 세트 자리» 함정에 걸렸었다.
파일을 엉뚱한 소스 세트에 두었는데 빌드가 아무 말도 안 하고 통과했다.

같은 병이다. **도구가 조용히 실패하고, 돌린 쪽은 돌렸다고 믿는다.**

그래서 규칙을 하나 세웠다.

> 배포는 «돌렸다»가 아니라 **«확인했다»** 로 끝난다.

명령이 0을 반환한 것은 확인이 아니다. 스토어에 있는 파일의 해시가
내 파일의 해시와 같은 것이 확인이다.
