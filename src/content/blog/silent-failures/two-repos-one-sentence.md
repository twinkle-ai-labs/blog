여러 저장소의 커밋을 날짜별 일지에 모으는 도구를 만들었습니다. 루트 저장소와 각 제품 저장소를 읽고, 커밋 해시가 같으면 중복으로 처리했습니다. 그런데 같은 작업이 일지에 두 번 적혔습니다.

제품을 루트에서 별도 저장소로 옮긴 뒤 생긴 문제였습니다. 며칠 사이에 겪은 자동화 문제 세 가지 중 첫 번째입니다. 나머지 두 가지는 등록정보 업로드가 통째로 실패한 일과, 이력을 다시 쓴 뒤 검사에 필요한 해시가 사라진 일이었습니다.

## 저장소를 옮기면 커밋 해시도 달라집니다

제품을 `git subtree`로 분리하거나 복사해 옮겨도 루트 저장소에는 과거의 커밋 메시지가 남습니다. 제품 저장소에 옮겨진 이력과 나란히 읽으면 같은 작업을 두 번 만날 수 있습니다.

```
루트 저장소     …  "물타기 계산기 키패드 서랍을 다시 짠다"  ← 3f2a1b9
제품 저장소     …  "물타기 계산기 키패드 서랍을 다시 짠다"  ← c84d0e7
```

두 커밋은 같은 작업을 설명하지만 해시가 다릅니다. 해시만 비교하는 도구는 둘을 별개의 기록으로 받아들였습니다.

커밋 해시는 파일 내용만으로 정해지지 않습니다. 트리뿐 아니라 부모 커밋, 시각, 작성자와 커미터 정보도 포함합니다. 이력을 옮기면서 부모가 달라지면 내용이 같아도 해시가 달라집니다. `cherry-pick`이나 `rebase`에서도 같은 일이 생길 수 있습니다.

필요했던 것은 동일한 커밋 객체를 찾는 검사가 아니라, 옮겨진 이력에서 같은 작업을 알아보는 기준이었습니다.

## 당시에는 날짜와 제목을 기준으로 삼았습니다

두 저장소에 남은 기록에서 공통으로 읽을 수 있는 것은 작업 날짜와 커밋 제목이었습니다. 이를 조합해 중복을 판정하도록 바꿨습니다.

```
날짜 + 제목
```

저장소가 달라도 같은 날 같은 제목으로 적힌 작업은 하나로 묶었습니다. 다만 이 방법은 제목이 다른 작업을 구분할 만큼 구체적이라는 전제가 필요했습니다.

```
✗  fix
✗  update
✗  wip

○  키패드 서랍이 나가는 곡선으로 떠나게 한다
○  aapt 가 접는 줄바꿈을 검사가 잡게 한다
```

같은 날 서로 다른 작업에 `fix`라는 제목을 붙이면 이 기준으로는 구별할 수 없습니다. 둘 중 하나가 빠집니다. 커밋 메시지는 일지를 읽는 사람뿐 아니라 중복을 판정하는 도구의 입력이기도 했습니다.

## 이력을 다시 써도 기존 일지는 남겨야 했습니다

나중에는 기록을 삭제하는 방식에서도 문제가 생겼습니다. 스쿼시나 리베이스로 이력을 다시 쓰면, 예전에 수집한 커밋을 현재 저장소에서 찾지 못할 수 있습니다.

루트를 두 커밋으로 다시 썼을 때 실제로 옛 기록 156줄이 일지에서 지워졌습니다. 도구가 현재 이력에 없는 커밋을 일지에서도 제거했기 때문입니다.

이후에는 표식 안에 이미 있던 줄과 새로 찾은 줄을 합쳐서 기록하도록 바꿨습니다. 현재 이력에서 커밋을 찾지 못한다는 이유로 당시의 작업 기록까지 지우지 않게 한 것입니다.
