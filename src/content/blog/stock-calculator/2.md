물타기 계산기는 앱을 구현하기 전에 HTML 목업에서 화면을 확인했습니다. 첫 커밋에는 앱과 목업이 함께 들어 있습니다.

    Initial commit: add stock calculator app and design mockup

```
stock-calculator/
├── design/    ← 화면 설계 + 디자인 토큰 (mockup.html)
└── app/       ← 안드로이드 소스
```

`design/mockup.html` 한 장에 계산기, 이력, 설정, 시트, 확인창, 키패드 서랍을 넣었습니다. 브라우저에서 화면을 열고 조작한 뒤 안드로이드 앱으로 옮기는 방식이었습니다.

## HTML 목업을 선택한 이유

Figma 대신 HTML을 쓴 이유는 토큰, 움직임, 화면 폭을 코드로 확인할 수 있어서였습니다.

`:root`에 색, 간격, 모서리, 움직임을 CSS 변수로 정의했습니다. 앱의 토큰 표를 만들 때도 이 값을 기준으로 삼았습니다.

```css
:root {
  --s1: 8px;   --s1h: 12px;  --s2: 16px;
  --radius-card: 18px;
  --ease: cubic-bezier(.25,1,.5,1);
  --exit: cubic-bezier(.4,0,1,1);
}
```

시트가 올라오는 속도와 키패드가 닫히는 곡선은 직접 열고 닫으며 조정했습니다. 정지 화면만으로는 느린 반응을 판단하기 어려웠습니다.

화면 폭은 고정한 iframe 안에서 `scrollWidth`와 `clientWidth`를 비교했습니다. 처음에는 헤드리스 브라우저의 스크린샷만 보고 판단하려다 혼동했습니다. 당시 환경에서는 `--window-size=390`을 줘도 캡처만 390px로 잘리고 레이아웃은 489px로 그려졌습니다. 잘린 오른쪽을 가로 스크롤 문제로 오인할 뻔했습니다. 이후에는 캡처와 실제 레이아웃 치수를 따로 확인했습니다.

## 결정한 이유도 함께 기록했습니다

혼자 만들다 보니 화면을 바꾼 이유를 기억에만 맡기기 쉬웠습니다. 그래서 기록의 용도를 나눴습니다.

- 저장소 루트 원칙 문서: 브랜드, 디자인 시스템, 엔지니어링 기준
- `CHANGELOG.md`: 버전별 사용자 변화와 내부 변경
- 기록용 금고: 판단의 이유와 작업 중 배운 내용

`CHANGELOG.md`에는 되돌린 결정도 남겼습니다.

```
- 되돌림: 통화 기호를 «원» 접미사로 시작했다가 ₩ 접두사로
  — 일곱 언어가 생긴 순간 «원»은 한국어를 읽는 사람에게만 통하는 그림이 된다
- 되돌림: 이름 입력 시트의 자동 포커스
  — 얼굴 피커와 함께 서면서 자판이 시트를 가린 채 튀어서
```

실제로 연보라를 제거하려는 시도를 두 번 했습니다. 두 번째에는 이전 기록을 읽고 왜 되돌렸는지 확인한 뒤 멈췄습니다.

## 목업과 앱을 함께 수정하던 시기

초기에는 목업에서 먼저 색, 간격, 배치를 바꿨습니다. 브라우저에서 확인해 괜찮으면 앱에 옮기고, 앱에서 새로 확인한 차이는 목업에 반영했습니다. 커밋에도 그 작업이 남아 있습니다.

    Design: 목업 키패드 서랍·이력 머리줄 2단·길게 누름 시트 영수증 구조를 앱과 한 벌로 정렬

2주 중 마지막 사흘은 디자인을 정리하는 데 대부분을 썼습니다.

    Design: 연보라 걷어내기 — sunken을 primarySoft와 갈라놓고…
    Design: sunken을 #F5F4F8로 한 칸 더 밝게
    Design: 홈 세그먼트 트랙을 흰 면(surface)으로
    Design: 바탕 위에 서는 것들을 흰 면으로

연보라를 제거하니 파인 면이 회색으로 보였고, 그 면을 밝히자 세그먼트 트랙과 구분이 어려워졌습니다. 주변 색과 함께 확인하면서 같은 부분을 네 번 수정했습니다.

키패드의 바깥을 누르면 닫히는 동작도 세 번 바꿨습니다. 투명한 입력 영역을 위에 덮었다가 아래에 두었고, 마지막에는 다른 요소가 처리하지 않은 탭을 받는 방식으로 정리했습니다.

## 언어는 한국어 화면을 정리한 뒤 늘렸습니다

8월 18일에 영어를 추가했고, 8월 22일에 아홉 개 언어를 더했습니다. 한국어로 화면과 문구를 먼저 정리한 뒤 열한 개 언어로 늘린 순서였습니다. 문구가 바뀔 때마다 모든 번역을 고치는 일을 줄일 수 있었습니다.

다만 문자열을 리소스에 두는 규칙은 처음부터 지켰습니다. 서식도 예외로 두지 않았습니다.

```kotlin
// 이렇게 쓰는 순간 그 화면은 한국어 전용이 됩니다
Text("${amount}원")
```

위처럼 단위를 코드에 붙이면 한국어에 맞춘 화면이 됩니다. 날짜 서식, `%1$s주` 같은 단위, 통화 이름 옆의 괄호까지 문자열 리소스에 뒀습니다.

일본어와 중국어는 전각 괄호（）를 쓰며 앞에 공백을 넣지 않습니다. 코드에서 `" (" + symbol + ")"`로 조합하면 이런 차이를 번역으로 바꿀 수 없습니다. 리소스에 서식을 함께 두었기 때문에 아홉 개 언어를 추가할 때 화면 코드 대신 번역을 작업할 수 있었습니다.

## 8월 22일에 목업 동기화를 멈췄습니다

2026년 8월 22일의 다음 커밋을 마지막으로 목업을 앱에 맞추는 일을 멈췄습니다.

    Design: 목업 시트 동기화 마무리 — 확인창 부제·선택지 두 줄, 종목 삭제/이력 삭제 문구를 앱과 한 벌로

앱이 없을 때는 Compose를 다시 빌드하는 것보다 브라우저를 새로고침하며 화면을 고르는 편이 빨랐습니다. 목업의 `:root`에 정의했던 값들은 이후 [Aurora Ledger](/design-system/aurora-ledger.html)의 기준이 됐습니다.

앱이 갖춰진 뒤에는 실제 앱에서 확인하는 편이 빠른 문제가 늘었습니다. 열한 개 언어의 글자 길이, 자판이 시트를 가리는 범위, 기기의 스크롤 관성과 길게 누름, 시스템 글꼴 크기에 따른 배치는 HTML만으로 확인하기 어려웠습니다. 이를 재현하려면 목업에도 별도의 구현이 필요했습니다.

8월 22일에는 안내 시트의 ‘그대로입니다’가 ‘그대로입니 / 다’로 끊기는 것을 발견했습니다. 목업 CSS에는 `keep-all`이 있었지만 앱에는 그에 맞는 처리가 없었습니다. 목업에서 맞게 보인다는 사실로 앱의 줄바꿈을 보장할 수 없었습니다.

이때부터는 앱을 기준으로 확인하고 수정하기로 했습니다. 두 구현을 계속 맞추는 데 드는 비용에 비해 목업에서 얻는 정보가 줄어들었기 때문입니다. [색 표가 여러 벌로 갈라졌던 작업](/design-system/light-dark-one-copy.html)과도 비슷한 관리 문제였습니다.

목업 파일은 지우지 않았습니다. 초기 화면을 결정한 과정과 토큰의 출발점을 볼 수 있도록 저장소에 남기고, 앱과 동기화하는 역할만 끝냈습니다.
