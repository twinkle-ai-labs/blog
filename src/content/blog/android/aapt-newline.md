설정 화면에서 안내 문장 두 개가 붙어 보였습니다.

> 선택 안 해도 계산 가능 나중에 이력에서 변경

`strings.xml`에는 두 줄로 적혀 있었습니다.

```xml
<string name="stock_optional_hint">선택 안 해도 계산 가능
나중에 이력에서 변경</string>
```

첫 줄은 종목을 선택하지 않아도 계산할 수 있다는 뜻이고, 둘째 줄은 나중에 이력에서 바꿀 수 있다는 뜻입니다. 줄바꿈이 사라지면서 두 안내의 경계도 사라졌습니다.

## 자원 파일의 줄바꿈과 화면의 줄바꿈

안드로이드 자원 컴파일러 aapt는 문자열 자원 안에서 이어지는 공백을 하나로 접습니다. XML의 들여쓰기나 줄바꿈이 그대로 화면에 나오는 것을 막는 처리입니다.

```xml
<!-- 적은 것 -->
<string name="a">첫 줄
둘째 줄</string>

<!-- 화면에 나오는 것 -->
첫 줄 둘째 줄
```

파일에서 엔터 키로 바꾼 줄도 이 처리에 포함됩니다. 화면에서 줄을 나누려면 `\n`을 명시해야 합니다.

```xml
<string name="a">첫 줄\n둘째 줄</string>
```

## 네 문자열과 열한 언어에서 같은 문제가 있었습니다

문자열을 더 찾아보니 같은 방식으로 적은 안내가 넷이었습니다. 그중 둘은 각 문장에 마침표가 있어 붙어도 읽을 수 있었습니다.

> "A입니다. B입니다." → "A입니다. B입니다."

문제가 눈에 띈 안내는 마침표 없이 짧게 끝나는 문구였습니다.

> "선택 안 해도 계산 가능" + "나중에 이력에서 변경"
> → "선택 안 해도 계산 가능 나중에 이력에서 변경"

번역된 열한 언어에도 같은 줄바꿈이 들어 있었습니다. 번역 파일에는 원문처럼 두 줄이 보였지만, 자원을 컴파일하면 모두 공백으로 바뀌었습니다. 빌드와 린트는 이 형식을 오류로 보지 않았습니다. 파일을 읽거나 빌드 결과만 확인해서는 화면에서 두 안내가 붙는다는 사실을 알기 어려웠습니다.

## 줄바꿈을 검사하고, 검사가 실패하는지도 확인했습니다

번역 완성도 검사인 `TranslationCompletenessTest`에 문자열 내부의 실제 줄바꿈을 찾는 규칙을 추가했습니다. `\n`으로 적은 줄바꿈은 허용하고, 파일에서 직접 줄을 나눈 경우를 잡도록 했습니다.

검사를 만든 뒤에는 일부러 잘못된 문자열을 넣었습니다.

```
1. strings.xml 에 두 줄짜리 문자열을 하나 심는다
2. 검사를 돌린다
3. 빨간불이 뜨는 것을 확인한다
4. 심은 것을 걷는다
```

의도한 입력에서 검사가 실패하는지 먼저 확인했습니다. 그래야 이후 통과 결과를 보고 해당 줄바꿈을 검사했다고 판단할 수 있습니다.

## 읽을 수 있던 문장도 함께 수정했습니다

마침표가 있어 뜻이 통하던 두 문자열에서도 실제 줄바꿈을 제거했습니다. 파일에서 보이는 형식과 화면의 동작을 맞추기 위해서입니다. 잘못된 예가 남아 있으면 새 안내를 추가할 때 같은 방식으로 줄을 나누기 쉽습니다.

이번에는 네 문자열과 번역을 함께 수정했습니다. 앞으로 화면에서 나뉘어야 하는 줄은 `\n`으로 적고, 실제 줄바꿈이 문자열 자원에 들어오면 검사에서 확인합니다.
