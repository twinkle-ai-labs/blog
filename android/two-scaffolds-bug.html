안드로이드를 만들며 12 — 광고 아래 여백을 만든 두 겹의 Scaffold

AdMob 배너 아래에 빈 공간이 생겼지만 광고 뷰의 크기는 정상이었습니다. 상위 Scaffold와 내부 Scaffold에서 하단 인셋이 두 번 적용되는 것을 확인하고 비슷한 화면 문제를 함께 조사했습니다.

#안드로이드#Compose#Scaffold#인셋#UI버그
✦ Heejeong KimTwinkle AI Labs
이 글의 목차⌄
  • 상위 화면에서 하단 인셋을 두 번 적용했습니다
  • 다른 화면의 유사한 문제도 확인했습니다
  • 여백 값을 바꾸기 전에 적용 경로를 확인합니다

화면 하단에 AdMob 적응형 배너를 붙인 뒤 광고와 기기 내비게이션 바 사이에 빈 띠가 생겼습니다. 광고 높이나 AndroidView의 크기, 픽셀 변환을 의심할 수 있는 모습이었습니다.

먼저 레이아웃 인스펙터로 광고 컨테이너를 확인했습니다. Box, FrameLayout, AdView가 모두 1078 × 168 px이었습니다. 측정한 광고 뷰 사이에는 1픽셀의 크기 차이도 없었습니다. 광고 자체보다 바깥의 배치를 살펴봐야 했습니다.

상위 화면에서 하단 인셋을 두 번 적용했습니다

화면 구조를 따라 올라가니 앱 내비게이션의 Scaffold 안에 탭 화면의 Scaffold가 또 있었습니다.

// 최상위 앱 내비게이션 레벨
Scaffold(
    bottomBar = { /* ... */ }
) { paddingValues ->
    // 각 탭별 개별 화면 레벨
    Scaffold(
        modifier = Modifier.padding(paddingValues) // 1차 시스템 인셋 적용
    ) { innerPadding ->
        // 콘텐츠 화면
        Column(modifier = Modifier.padding(innerPadding)) { // 2차 시스템 인셋 또 적용!
            ...
            AdBanner()
        }
    }
}

Scaffold는 시스템 인셋 등을 반영한 패딩을 콘텐츠에 전달합니다. 이 화면에서는 바깥의 paddingValues를 적용한 뒤, 내부 Scaffold의 innerPadding에서도 하단 인셋을 다시 적용하고 있었습니다.

광고가 차지하는 높이는 맞았지만 광고를 포함한 화면 전체가 이중 패딩의 영향을 받았습니다. 여백의 원인은 광고 바로 아래가 아니라 광고를 감싸는 상위 구조에 있었습니다.

다른 화면의 유사한 문제도 확인했습니다

인셋 문제를 찾은 뒤 같은 구조를 사용하는 화면을 조사했습니다. 확인한 문제는 네 종류였습니다.

문제확인한 범위
PDF 뷰어에서 뒤로 나온 뒤 결과 바텀시트가 다시 표시됨4개 화면
바텀시트와 본문에서 하단 시스템 패딩이 중복됨3개 화면
데이터가 없을 때 일러스트가 위로 치우침2개 화면
기기를 회전하면 툴바 액션 아이콘 상태가 초기화됨회전 시 상태 처리

이 문제들이 모두 광고 배너에서 생긴 것은 아니었습니다. 한 화면에서 발견한 증상을 계기로, 복제된 화면 구조와 상태 처리를 함께 확인했습니다.

여백 값을 바꾸기 전에 적용 경로를 확인합니다

광고의 패딩을 음수로 줄이거나 임의의 Spacer(height = 16.dp)를 넣는다면 눈앞의 간격만 맞출 수 있습니다. 하지만 하단 인셋을 두 번 적용한 구조는 남습니다.

이번에는 광고 뷰의 크기를 먼저 측정한 뒤 WindowInsets와 paddingValues가 전달되고 적용되는 위치를 확인했습니다. Scaffold가 중첩됐다는 사실만으로 오류가 되는 것은 아니며, 같은 인셋이 어디에서 적용되는지를 봐야 했습니다. 이 경로를 확인한 뒤 다른 화면에서도 같은 패딩 처리와 상태 복제 문제가 있는지 살폈습니다.
